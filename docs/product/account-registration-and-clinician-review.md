# 账号、医护申请和研发管理

2026-10-15 确认的本批需求与验收标准。

| 需求 | 本批实现 |
| --- | --- |
| 手机号与短信验证码登录 | 已记录为下一批；用户确认尚无短信服务配置，本批保留账号密码登录。不使用固定验证码或假短信代替真实验证 |
| 医护患者汇总 | 有效授权患者列表，每行仅姓名、账号 ID；点击读取该患者的健康档案及已有设备数据，仍为只读 |
| 医护自行注册 | 登录首页提供医护注册入口，填写姓名、账号和所属机构；申请须由研发管理账号审批，通过前没有医护访问权 |
| 研发账号管理入口 | 现有 researcher 身份显示研发管理，能创建医护账号、添加已有患者账号为医护、审批医护申请 |
| 人员汇总图表 | 实时统计已注册账号总数、患者、医护、开发协作者；按当前身份互斥统计，待审批账号审批前仍为患者身份 |
| 数据权限 | 研发管理权限不自动开放患者健康资料；医护只有患者当前有效授权后才能查看，撤销后下一次查询即拒绝 |

新注册填写姓名；旧账号没有姓名时明确显示“未填写姓名”，不把用户名当作姓名。患者可在医护授权页补充自己的姓名。开发协作者人数对应 researcher 身份；新增该身份仍由维护者命令完成，不提供公开自选入口。

医护申请支持待审批、通过、拒绝和拒绝后重新提交；记录申请人与审核人、时间、拒绝原因，审核并发时只能完成一次。直接添加已有账号为医护也必须由研发账号执行，并记录角色变更和终止旧授权。

用户验收链路：医护注册申请 → 研发看到待审批 → 通过后医护刷新身份进入医护列表 → 患者授权 → 点击列表行查看详情 → 患者撤销后查询被拒绝。另验证拒绝后重申、研发创建/添加医护、总览人数随身份变更更新。

实现依据：按 [OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html) 在服务器逐请求校验身份和关系、默认拒绝。新增管理行为不扩大患者资料读取范围。列表与统计只读取所需账户字段，避免把健康正文加入管理数据。
